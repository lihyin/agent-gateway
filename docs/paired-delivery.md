# Pairing and foreground encrypted delivery

The primary flow is [Pair with Muse using a one-time code](pin-pairing.md): tap,
copy one setup message to Muse, then approve and authenticate on the phone.
Offers and receipts transfer automatically over an SRP-authenticated channel.
The instructions below are the **Advanced: manual pairing** fallback, which pins
one device and one agent with two-way fingerprint comparison and device
authentication. Automatic relay-only APNs delivery is implemented; see
[setup](remote-delivery.md). The agent client runs inside Muse, without a hosted
bridge or callback server. This page also documents manual encrypted transfer as
a fallback. Real provider/device acceptance remains required.

## Agent setup

For production Muse delivery, run these commands inside Muse runtime. A local
terminal is only a development/manual-transfer fallback. No hosted bridge is needed.

Run `npm ci` and `npm run build --workspace agent-adapter`. The CLI is
`agent-adapter/dist/src/cli.js`. Set a private, backup-excluded state path:

```powershell
$env:GATEWAY_AGENT_STATE = "$PWD\.tools\local-agent\state.json"
node agent-adapter/dist/src/cli.js offer
```

The command prints a signed `offer` and public SHA-256 `fingerprint`. Never
transfer the state file: it contains agent private keys. Newly written files use
current-user Windows ACLs or POSIX mode 0600, atomic replacement and an exclusive
process lock. Use OS disk encryption. State is agent-owned, never relay-owned.

## Pair the phone

1. Expand **Advanced: manual pairing**. Paste only `offer` into **Signed agent pairing offer** on the iPhone.
2. Enter the full `fingerprint` from the trusted agent terminal into **Agent
   fingerprint from trusted terminal**. Do not trust an unsolicited fingerprint.
3. Tap **Verify and pair agent** and authenticate on the device.
4. Independently compare the displayed **Device fingerprint** through a trusted
   channel. Save the phone's pairing receipt as `receipt.txt` on the agent host.
5. Within five minutes run:

```powershell
node agent-adapter/dist/src/cli.js accept receipt.txt <full-device-fingerprint>
```

The agent verifies the device signature, offer digest/nonce, expiry, and device
fingerprint before pinning both keys. If transfer is interrupted or expires,
unpair on the phone and generate a fresh offer. Each pairing gets a fresh epoch.

## Deliver a request and approved result

Create `request.json` with this shape. Replace `since` and `until` with current
UTC Unix seconds: seven days ago and now respectively.

```json
{
  "source": "gmail",
  "operation": "search",
  "query": "subject:AGWTEST",
  "purpose": "Test invoice preview",
  "fields": ["id", "date", "subject"],
  "since": 1791057600,
  "until": 1791662400,
  "maxResults": 5
}
```

```powershell
node agent-adapter/dist/src/cli.js request request.json
```

1. Connect Gmail on the phone. Paste just the returned `envelope` JSON into
   **Encrypted request envelope** and tap **Import encrypted request**.
2. Check the paired agent ID, purpose, query, fields and expiry on the review card.
3. **Allow Gmail access** permits fetching, not disclosure. Review the filtered
   preview and choose Allow once, Deny, Edit, or a scoped Always rule.
4. Tap **Export encrypted result** and **Copy encrypted transfer**. Save that
   ciphertext JSON as `result.json` on the agent host and run:

```powershell
node agent-adapter/dist/src/cli.js submit result.json
```

Only this final command decrypts the approved result on the paired host. Denials
carry no source data. Finish within the original five-minute request expiry;
review does not extend it. Sender/snippet require device authentication. Unpair
on the phone for immediate local revocation, then run CLI `unpair` to erase
agent-side jobs/pinned device keys.

## Security, recovery, and limits

- ES256 signing and RSA-2048 encryption keys are separate. Nested compact JWS/JWE
  uses RSA-OAEP-256/A256GCM with exact algorithm headers and bound context.
- Both public keys are fingerprinted; request/result recipient keys are pinned.
  Direction, identities, epoch, request ID and expiry are checked before review.
- Device keys are generated by the JOSE library in an isolate and stored in
  device-only unlocked Keychain. Secure Enclave operations are not claimed.
- Durable identity/digest reservation precedes review. Same-ID changed ciphertext
  fails. Restart preserves deduplication; disconnect cannot reopen an old request.
  Interrupted reservation without review fails closed: create a new request ID.
- Release rechecks approval revision/digest, pairing and expiry. Re-export returns
  identical saved ciphertext and cannot repeat retrieval. Storage failure disables
  further transitions until successful reinitialization.
- At most 20 reservations/jobs are kept, for at most 24 hours after expiry. Phone
  outcome files contain ciphertext. The agent can retain approved plaintext after
  decrypting; the phone cannot revoke already disclosed data.
- The advanced manual flow copies public pairing material/ciphertext. The code
  flow's setup message also contains its short-lived secret PIN: send it only to
  trusted Muse and keep it out of logs. Google credentials and device private
  keys are never exported.
- Remove a stale agent `.lock` file after a crash only after verifying no process
  uses that state. Do not share one state file across users. Disk loss requires
  re-pairing. Relay-only notification transport uses the same protected domain pipeline.

Cross-runtime fixtures verify real receipts and encrypted results with public,
disposable test-only keys. Physical-device acceptance is still required: check
fingerprint comparison/cancellation, Keychain persistence, locked-device behavior,
and approval/export in TestFlight. Mock tests do not establish these checks.
